# AIccounting 软件配置与运维文档

## 2. 系统架构概述

### 2.1 系统组成
AIccounting系统采用多层架构设计，包含以下核心组件：

#### 后端服务层

AIccounting后端服务层采用Python 3.x技术栈，结合PyMySQL数据库连接组件构建。该层主要负责AI记账逻辑处理和数据存储管理功能。服务部署在`AIccounting-main/`目录下，以命令行交互式应用的模式运行，为用户提供智能记账助手服务。

#### Web前端层

Web前端层基于Vue.js 2.5.2框架开发，配合Webpack构建工具和Axios HTTP客户端实现。该层承担用户界面展示和交互逻辑处理的职责。应用部署在`App/`目录下，采用单页面应用（SPA）架构模式运行，为用户提供流畅的Web端操作体验。

#### 移动端应用层

移动端应用层采用Vue 3.3.8现代化框架，结合Vite快速构建工具和Cordova跨平台解决方案开发。该层专门负责移动设备原生应用支持功能。应用代码位于`App-Mobile/`目录下，目标平台为Android系统，为用户提供便捷的移动端记账服务。

### 2.2 数据存储架构

AIccounting系统采用混合数据存储架构设计。主数据库采用MySQL 8.0关系型数据库管理系统，数据库实例名称为"data"，负责核心业务数据的持久化存储。移动端采用SQLite轻量级数据库，通过cordova-sqlite-storage插件实现本地数据存储功能。系统整体以本地存储为主导模式，当前版本不包含云端数据同步机制，确保用户数据的本地化管理和隐私保护。

## 3. 环境配置管理

### 3.1 开发环境要求

#### 基础软件依赖
| 组件 | 版本要求 | 用途 |
|------|----------|------|
| Python | 3.x+ | 后端运行环境 |
| Node.js | 16.x+ | 前端构建环境 |
| MySQL | 8.0+ | 数据存储服务 |
| Android SDK | 最新版 | 移动端构建支持 |

#### Python依赖管理

后端服务的核心依赖库包括pymysql数据库连接组件，该组件负责MySQL数据库的连接和操作功能。系统的其他Python依赖项需要通过检查`AIccounting-main`目录下源代码文件中的import语句来确定具体的依赖关系和版本要求。

#### Node.js依赖管理

前端项目的依赖关系管理采用标准的Node.js包管理机制。Web前端项目的依赖配置定义在`App/package.json`文件中，移动端项目的依赖配置定义在`App-Mobile/package.json`文件中。各项目的依赖安装和版本管理通过npm包管理器统一处理。

### 3.2 配置文件体系

#### 数据库配置
配置位置：`AIccounting-main/sql.py`
```python
class MySQLDataStore:
    def __init__(self, host="localhost", port=3306, user="root", password="512560", db="data")
```

#### Web前端配置

Web前端的环境配置文件统一存放在`App/config/`目录下，采用分环境配置管理策略。开发环境配置文件为`dev.env.js`，负责本地开发环境的参数设置。生产环境配置文件为`prod.env.js`，用于生产部署时的环境参数配置。测试环境配置文件为`test.env.js`，专门为测试阶段提供相应的环境配置支持。

#### 移动端配置

移动端应用的核心配置信息集中在`App-Mobile/package.json`文件中进行管理。该配置文件包含Cordova框架版本设置、相关插件依赖声明以及构建脚本配置等关键信息，为移动端应用的开发和构建提供完整的配置支持。

## 4. 部署策略

### 4.1 本地开发部署

#### 环境初始化流程

本地开发环境的初始化需要按照规范化流程进行。首先进行数据库准备工作，包括创建MySQL数据库实例和执行表结构初始化操作。随后在各子项目目录中安装对应的依赖包，确保所有必要的组件和库文件正确安装。最后进行配置验证步骤，确认数据库连接参数设置正确，环境变量配置符合要求。

#### 服务启动序列

系统服务的启动需要遵循特定的序列顺序以确保各组件间的依赖关系得到正确处理。首先确保MySQL数据库服务处于正常运行状态，为后续服务提供数据支持。然后通过执行`python main.py`命令启动AI记账助手后端服务。接着通过`npm run dev`命令启动前端开发服务器，提供Web界面访问支持。最后使用Cordova工具链进行移动端APK构建，完成移动应用的打包工作。

### 4.2 生产环境考虑

当前AIccounting系统版本主要面向本地化部署场景设计。在考虑生产环境部署时，需要重点关注数据库安全配置优化，包括用户权限管理、连接加密和访问控制策略。静态资源CDN部署方案需要评估前端资源的分发策略，优化用户访问体验。移动应用商店发布流程需要遵循相应平台的审核规范和技术要求，确保应用能够顺利上架和分发。

## 5. 运维监控体系

### 5.1 系统监控策略

考虑到AIccounting系统采用本地化架构设计的特点，系统监控策略主要依赖内置的监控机制和操作系统级别的工具。数据库连接监控通过`main.py`程序中集成的连接测试功能实现，能够及时发现和报告数据库连接异常情况。应用状态监控基于命令行输出信息和日志记录机制，提供应用运行状态的实时反馈。资源使用监控依赖操作系统级别的监控工具，如任务管理器或系统监视器，用于跟踪CPU、内存和磁盘使用情况。

### 5.2 日志管理规范

系统日志管理采用分层分类的管理规范。后端日志直接集成在主程序中，负责输出关键操作信息、错误信息和调试信息，确保系统运行状态的可追溯性。前端日志可以通过Vue.js框架提供的错误处理机制进行收集和管理，包括组件错误、路由错误和JavaScript运行时错误。测试日志通过专门的测试套件自动生成，记录测试执行过程、结果统计和性能指标等信息。

### 5.3 数据备份策略

系统数据备份策略涵盖多个层面的数据保护需求。数据库备份采用MySQL标准工具实现定期自动备份，确保核心业务数据的安全性和可恢复性。移动端数据备份通过应用内置的导出功能实现，允许用户主动备份本地数据到外部存储。配置备份依托版本控制系统管理配置文件的变更历史，确保配置修改的可追溯性和可回滚性。

## 6. 质量保证体系

### 6.1 测试框架
系统集成了完整的测试体系：

#### 后端测试

后端测试框架部署在`AIccounting-main/tests/`目录下，包含完整的测试组件体系。主程序功能测试通过`test_main.py`文件实现，负责验证核心业务逻辑的正确性。数据库操作测试通过`test_sql.py`文件实现，确保数据存储和查询功能的可靠性。接口功能测试通过`test_api.py`文件实现，验证API接口的功能完整性和数据格式正确性。测试执行调度器`run_tests.py`负责统一管理和执行所有测试用例。性能压力测试通过`locustfile.py`实现，提供系统负载测试和性能基准评估功能。

前端测试采用Jest测试框架，相关配置信息在`App/package.json`文件中定义。测试范围包括单元测试和组件测试两个层面，单元测试负责验证独立功能模块的正确性，组件测试负责验证Vue组件的渲染逻辑和交互行为。

代码质量管理体系包含多个层面的质量控制措施。静态代码检查通过ESLint等专业工具进行代码规范检查，确保代码风格的一致性和潜在问题的早期发现。依赖安全扫描机制负责定期检查第三方依赖库的安全漏洞，及时发现和处理安全风险。性能基准测试使用Locust工具进行性能回归测试，确保系统性能指标在版本迭代过程中保持稳定。

## 7. 故障处理规范

### 7.1 常见故障分类与处理

#### 数据库连接故障

数据库连接故障是系统运行中常见的问题类型，主要表现为应用启动时出现MySQL连接错误信息。故障处理流程包括四个关键步骤：首先验证MySQL服务的运行状态，确保数据库服务正常启动；其次检查数据库实例和用户权限配置，确认访问权限设置正确；然后确认网络连接和防火墙设置，排除网络层面的连接障碍；最后验证`sql.py`文件中连接参数的正确性，确保配置信息与实际环境匹配。

#### 依赖环境故障

依赖环境故障通常表现为npm或pip安装失败、模块导入错误等症状。标准处理流程包括四个步骤：首先清理包管理器缓存，消除缓存污染导致的安装问题；其次验证Node.js和Python版本的兼容性，确保运行环境满足项目要求；然后检查网络连接和代理设置，确保包下载渠道畅通；必要时重建虚拟环境，彻底解决环境污染问题。

#### 移动端构建故障

移动端构建故障主要表现为Cordova构建失败和APK生成错误等问题。处理流程包括四个关键环节：首先执行项目提供的`setup-cordova.bat`脚本进行环境配置，确保Cordova环境正确设置；其次清理Cordova缓存并重建平台，消除缓存数据对构建过程的影响；然后验证Android SDK和Java环境配置，确保构建工具链完整；最后检查插件兼容性和版本匹配，解决插件冲突问题。

### 7.2 故障预防机制

故障预防机制是确保系统稳定运行的重要保障。环境一致性检查通过定期验证开发环境配置，确保团队成员的开发环境保持统一标准，避免环境差异导致的问题。依赖版本锁定使用package-lock.json等机制锁定依赖版本，防止依赖更新导致的兼容性问题。自动化测试通过持续集成机制发现潜在问题，在问题扩散前及时识别和解决。
