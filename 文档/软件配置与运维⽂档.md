# AIccounting 软件配置与运维文档

本文档旨在为AIccounting智能记账系统提供完整的配置管理和运维操作指导，确保系统在各环境中的稳定运行。

## 1. 概述

### 1.1 文档目的
本文档提供AIccounting项目的配置管理和运维操作指南，包括环境配置、系统配置、服务部署、监控管理、故障处理等内容，帮助运维人员高效地管理和维护系统。

### 1.2 系统架构
AIccounting系统包含三个主要组件：
- **Flask API服务**：后端数据处理和接口服务
- **Vue.js Web应用**：网页端用户界面
- **Cordova移动应用**：Android移动端应用

各组件相对独立部署，通过标准化的配置管理和监控体系实现统一运维。

### 1.3 管理范围
本文档涵盖以下配置和运维内容：
- 环境配置和系统要求
- 版本管理和变更控制
- 服务部署和启停管理
- 系统监控和日志管理
- 故障处理和预防机制
- 团队协作和安全规范

#### 运维配置管理策略

系统配置管理基于源代码仓库的实际情况进行。配置信息主要通过源代码文件进行管理，包括数据库连接参数、API密钥等。开发和测试环境通过Git版本控制系统管理代码和配置文件的变更。配置修改直接在相应的源文件中进行，通过代码提交记录变更历史。

#### 依赖包版本管理

Python依赖包管理通过检查项目源代码中的import语句确定实际依赖关系。Node.js依赖包管理通过各目录下的package.json文件定义版本要求。移动端Cordova插件配置在App-Mobile目录的相关配置文件中。依赖包更新需要测试验证兼容性，确保系统正常运行。

### 2.3 配置文件运维管理

#### 核心配置文件清单
- **数据库配置**：`AIccounting-main/sql.py` - MySQL连接参数管理
- **Flask服务配置**：API服务启动参数和DeepSeek API密钥配置
- **Web前端配置**：`App/config/` - 环境变量和API端点配置
- **移动端配置**：`App-Mobile/package.json` - Cordova插件和构建配置

#### 配置变更管理流程

配置文件的变更通过Git版本控制系统进行管理。开发人员在本地环境修改配置文件后，通过Git提交记录变更内容。配置变更历史可通过Git日志查看，支持版本回滚操作。

#### 敏感信息管理

数据库密码、API密钥等敏感信息当前在源代码中直接配置。在生产环境部署时，需要修改源代码中的相关配置参数，确保使用正确的生产环境凭据。对DeepSeek API的管理，进行定期检查使用情况和余额状态，根据实际调用量及时进行续费充值，避免因余额不足导致服务中断影响用户体验。

## 3. 版本管理策略

### 3.1 版本命名规范

系统采用语义化版本控制（Semantic Versioning）规范，版本号格式为：**主版本号.次版本号.修订号（X.Y.Z）**

**版本号递增规则：**
- **主版本号（X）**：当进行大规模调整或者重大功能更新，同时次版本号和修订号归零，如：数据库结构重大变更、架构重大调整、添加全新大板块等
  
- **次版本号（Y）**：当添加新功能且向下兼容时递增，同时修订号归零，如：添加新功能、完善已有功能等
  
- **修订号（Z）**：当进行向下兼容的问题修复时递增，如：修复Bug、性能优化、代码重构等

### 3.3 版本回退策略

**回退决策条件：**
- 发布结果不符合预期
- 影响其他功能的正常使用
- 数据丢失或损坏风险

**回退执行流程：**
1. 立即停止问题版本的新部署
2. 使用Git revert或reset回退到稳定版本
3. 通知所有团队成员和用户
4. 分析问题原因并制定修复计划
5. 完成修复后重新测试和发布

## 4. 服务部署运维

### 4.1 部署环境管理

#### 环境分级管理
系统主要采用本地开发环境和生产部署环境的二级管理模式。开发环境用于日常开发和调试，生产环境用于正式服务运行。各环境的配置参数通过修改源代码文件进行差异化设置。

#### 服务部署流程
服务部署采用手工部署的方式，包括代码更新、依赖安装、配置修改、服务重启等步骤。部署前需要确认代码变更内容，部署后验证服务运行状态。

#### 部署管理
项目部署主要通过手工操作完成环境搭建、依赖安装、服务启动等步骤。部署过程需要按照文档说明逐步执行，确保各组件正确配置和启动。遇到问题时通过日志输出和错误信息进行故障排查。

### 4.2 服务启停管理

#### Flask API服务管理
Flask API服务通过命令行方式启动，使用python命令运行`api.py`启动脚本。服务运行时需要确保MySQL数据库服务正常运行，并验证数据库连接配置正确。服务状态可通过命令行输出信息和日志来监控。

#### Web前端服务管理
Web前端开发环境通过npm run dev命令启动开发服务器，默认运行在8080端口。生产环境可通过npm run build构建静态文件，然后使用任意Web服务器托管。前端服务状态通过浏览器访问验证。

#### 移动端应用管理
移动端应用通过Cordova工具链进行构建和打包。开发环境使用npm run dev启动，APK构建使用现有的setup-cordova.bat脚本配置环境。应用分发通过生成的APK文件进行本地安装测试。

## 5. 运维监控体系

### 5.1 系统监控策略

AIccounting系统采用本地化部署，监控主要依赖基础的监控方法。数据库连接状态通过应用启动时的连接测试进行验证，连接异常会在控制台输出错误信息。Flask API服务状态通过命令行输出和应用日志进行监控。Web前端应用状态通过浏览器访问和开发者工具进行检查。移动端应用状态通过设备上的应用运行情况进行观察。系统资源使用情况可通过操作系统的任务管理器或系统监视器进行查看。

### 5.2 日志管理规范

系统日志管理基于各组件的内置日志功能。Flask后端日志通过应用运行时的控制台输出进行查看，包括请求处理信息、错误信息和数据库操作状态。Web前端日志主要通过浏览器控制台查看，包括JavaScript错误、网络请求状态和组件运行信息。移动端应用日志可通过设备的开发者选项或Cordova调试工具查看。测试日志通过运行项目tests目录下的测试脚本自动生成。

### 5.3 数据备份策略

系统数据备份采用手工操作的方式进行管理。MySQL数据库可以使用mysqldump命令进行数据导出备份，定期执行备份操作确保数据安全。移动端数据通过LocalForage存储在浏览器本地存储中，可通过应用内的导出功能进行备份。源代码和配置文件通过Git版本控制系统进行备份，重要版本可以打标签保存。

## 6. 质量保证体系

### 6.1 测试框架
系统集成了完整的测试体系：

#### 后端测试

后端测试框架部署在`AIccounting-main/tests/`目录下，包含完整的测试组件体系。主程序功能测试通过`test_main.py`文件实现，负责验证核心业务逻辑的正确性。数据库操作测试通过`test_sql.py`文件实现，确保数据存储和查询功能的可靠性。接口功能测试通过`test_api.py`文件实现，验证API接口的功能完整性和数据格式正确性。测试执行调度器`run_tests.py`负责统一管理和执行所有测试用例。性能压力测试通过`locustfile.py`实现，提供系统负载测试和性能基准评估功能。

#### 前端测试

前端测试采用Jest测试框架，相关配置信息在`App/package.json`文件中定义。测试范围包括单元测试和组件测试两个层面，单元测试负责验证独立功能模块的正确性，组件测试负责验证Vue组件的渲染逻辑和交互行为。

### 6.2 代码质量管理

代码质量管理体系包含多个层面的质量控制措施。静态代码检查通过ESLint等专业工具进行代码规范检查，确保代码风格的一致性和潜在问题的早期发现。依赖安全扫描机制负责定期检查第三方依赖库的安全漏洞，及时发现和处理安全风险。性能基准测试使用Locust工具进行性能回归测试，确保系统性能指标在版本迭代过程中保持稳定。团队定期执行完整的测试套件验证系统功能正常运行，通过运行后端的`run_tests.py`和前端的Jest测试确保核心功能有无异常，及时发现和修复潜在的功能问题。

## 7. 故障处理规范

### 7.1 常见故障分类与处理

#### 数据库连接故障

数据库连接故障是系统运行中常见的问题类型，主要表现为应用启动时出现MySQL连接错误信息。故障处理流程包括四个关键步骤：首先验证MySQL服务的运行状态，确保数据库服务正常启动；其次检查数据库实例和用户权限配置，确认访问权限设置正确；然后确认网络连接和防火墙设置，排除网络层面的连接障碍；最后验证`sql.py`文件中连接参数的正确性，确保配置信息与实际环境匹配。

#### 依赖环境故障

依赖环境故障通常表现为npm或pip安装失败、模块导入错误等症状。标准处理流程包括四个步骤：首先清理包管理器缓存，消除缓存污染导致的安装问题；其次验证Node.js和Python版本的兼容性，确保运行环境满足项目要求；然后检查网络连接和代理设置，确保包下载渠道畅通；必要时重建虚拟环境，彻底解决环境污染问题。

#### 移动端构建故障

移动端构建故障主要表现为Cordova构建失败和APK生成错误等问题。处理流程包括四个关键环节：首先执行项目提供的`setup-cordova.bat`脚本进行环境配置，确保Cordova环境正确设置；其次清理Cordova缓存并重建平台，消除缓存数据对构建过程的影响；然后验证Android SDK和Java环境配置，确保构建工具链完整；最后检查插件兼容性和版本匹配，解决插件冲突问题。

### 7.2 故障预防机制

故障预防主要通过规范的开发和部署流程来实现。定期检查各开发环境的配置一致性，确保团队成员使用相同的开发工具版本和依赖配置。使用Git版本控制锁定依赖版本，避免随意更新导致的兼容性问题。在代码提交前运行测试套件验证功能正常，及时发现和修复潜在问题。
